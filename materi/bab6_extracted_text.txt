5. Rancang kebijakan retensi tujuh hari yang dapat dijalankan terjadwal tanpa mengunci tabel 
secara berlebihan. 
Membuat script scripts/purge-retention.sh 
 1. #!/usr/bin/env bash 
 2. set -euo pipefail 
 3.   
 4. DAYS="${1:-7}" 
 5. BATCH_SIZE="${2:-5000}" 
 6.   
 7. while true; do 
 8.   DELETED=$(docker compose exec -T postgres-db psql -U labadmin -d labdb -t -A -c " 
 9.     WITH to_delete AS ( 
10.       SELECT ctid FROM logs.fluentbit 
11.       WHERE time < NOW() - INTERVAL '$DAYS days' 
12.       LIMIT $BATCH_SIZE 
13.     ) 
14.     DELETE FROM logs.fluentbit 
15.     WHERE ctid IN (SELECT ctid FROM to_delete); 
16.   ") 
17.   COUNT=$(echo "$DELETED" | awk '{print $2}') 
18.   if [ -z "$COUNT" ] || [ "$COUNT" -eq 0 ]; then 
19.     break 
20.   fi 
21.   sleep 0.1 
22. done 
23.   
Analisis: Script scripts/purge-retention.sh dibuat untuk menghapus log yang berumur lebih dari 
tujuh hari secara bertahap (batch deletion). Proses penghapusan menggunakan Common Table 
Expression (CTE) dengan ctid sebagai penunjuk baris fisik dan LIMIT 5000 untuk membatasi 
jumlah record yang dihapus dalam setiap batch. Dengan cara ini, penghapusan tidak dilakukan 
sekaligus dalam jumlah besar sehingga beban database dapat lebih terkendali. Strategi ini juga 
membantu mengurangi potensi gangguan terhadap proses penulisan log baru dari Fluent Bit. 
Namun, penghapusan bertahap tidak sepenuhnya menghilangkan risiko lock contention 
maupun lonjakan Write-Ahead Logging (WAL)

6. Jelaskan mengapa PostgreSQL sesuai untuk laboratorium ini, tetapi belum tentu tepat untuk

PostgreSQL cocok untuk lab karena mudah dijalankan melalui Docker, mendukung JSONB,

table bloat dapat membuat penggunaan ruang disk meningkat akibat penghapusan data yang
